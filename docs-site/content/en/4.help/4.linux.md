The TRS Launcher runs on any x86_64 Linux with glibc 2.35 or newer (Ubuntu 22.04+, Debian 12+, Fedora 36+, Arch,
openSUSE Tumbleweed and others), on Wayland and X11. Java is downloaded automatically. This page covers what is
different on Linux and how to fix typical problems; installing is explained in [Installation](/en/getting-started/installation).

## Where things are

| What | Path |
|---|---|
| Launcher data (instances, Java, libraries) | `~/.local/share/TRS-Launcher` |
| Launcher data (Flatpak) | `~/.var/app/dev.theredstonee.trslauncher/data/TRS-Launcher` |
| Launcher log | `~/.local/share/dev.theredstonee.trslauncher/logs` |
| Sign-in key | the system keyring (Secret Service), otherwise `~/.local/share/TRS-Launcher/.token-key` (mode 0600) |

## Updates

Only the **AppImage** updates itself, like the Windows version. The `.deb`, `.rpm`, AUR and Flatpak packages are updated
by your package manager – the launcher tells you when a new version is out ("Update … available") and links to it.

## Sign-in keys and the keyring

The key that protects your Microsoft sign-ins is kept in the system keyring (GNOME Keyring, KWallet, KeePassXC with
Secret Service …). Without a keyring it is kept in a file only your user can read.

**Settings → Storage → Stored sign-ins** shows which one is used. If it says **File permissions only**:

::steps{level="3"}

### Set up a keyring

Install and unlock GNOME Keyring or KWallet, or turn on the Secret Service in KeePassXC.

### Restart the launcher

The key moves into the keyring by itself.

::

## Troubleshooting

### Blank or white window

Start the launcher with the DMA-BUF renderer of WebKit switched off:

```bash
WEBKIT_DISABLE_DMABUF_RENDERER=1 trs-launcher
```

With the proprietary NVIDIA driver the launcher does this by itself. On very old graphics cards also try
`WEBKIT_DISABLE_COMPOSITING_MODE=1`.

### The AppImage doesn't start ("FUSE")

The AppImage needs FUSE 2. Install it, or run the AppImage without FUSE:

::code-group

```bash [Debian/Ubuntu]
sudo apt install libfuse2
```

```bash [Arch]
sudo pacman -S fuse2
```

```bash [Without FUSE]
./TRS-Launcher_<version>_amd64.AppImage --appimage-extract-and-run
```

::

### Minecraft 1.12.2 or older crashes at the start

Old versions (LWJGL 2) need the `xrandr` tool:

::code-group

```bash [Arch]
sudo pacman -S xorg-xrandr
```

```bash [Debian/Ubuntu]
sudo apt install x11-xserver-utils
```

```bash [Fedora]
sudo dnf install xrandr
```

::

### The game runs on the wrong graphics card

On a laptop with two graphics chips, turn on **Settings → Default settings → High-performance graphics card**. The
launcher then sets `DRI_PRIME=1` (AMD/Intel) or the NVIDIA PRIME variables. Your own values under **Environment
variables** win.

### Tools like GameMode or prime-run

Put them in front of the game under **Settings → Launch hooks → Wrapper**, for example `gamemoderun` or `prime-run`.

### Importing from other launchers

Prism Launcher, MultiMC, the Modrinth App and `~/.minecraft` are found automatically, including their Flatpak versions.

::note
The Flatpak version can only read these known folders. For anything else, use **Browse folder** in the import dialog.
::

## Wayland

The launcher runs on Wayland and X11. The game itself runs through XWayland.

## Not available on Linux

- **Clip recording** and the **Windows firewall helper** (not needed on Linux).
- **ARM64**: there are no ARM builds, because Mojang has no Java runtime for ARM Linux and Minecraft 1.12.2 and older
  has no ARM natives.
