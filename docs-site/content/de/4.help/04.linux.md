Der TRS Launcher läuft auf jedem x86_64-Linux mit glibc 2.35 oder neuer (Ubuntu 22.04+, Debian 12+, Fedora 36+, Arch,
openSUSE Tumbleweed und weitere), unter Wayland und X11. Java wird automatisch heruntergeladen. Diese Seite zeigt, was
unter Linux anders ist und wie du typische Probleme löst; wie du ihn installierst, steht unter
[Installation](/de/getting-started/installation).

## Wo was liegt

| Was | Pfad |
|---|---|
| Launcher-Daten (Instanzen, Java, Libraries) | `~/.local/share/TRS-Launcher` |
| Launcher-Daten (Flatpak) | `~/.var/app/dev.theredstonee.trslauncher/data/TRS-Launcher` |
| Launcher-Log | `~/.local/share/dev.theredstonee.trslauncher/logs` |
| Anmeldeschlüssel | Schlüsselbund des Systems (Secret Service), sonst `~/.local/share/TRS-Launcher/.token-key` (Rechte 0600) |

## Updates

Nur das **AppImage** aktualisiert sich selbst, wie die Windows-Version. Die Pakete `.deb`, `.rpm`, AUR und Flatpak
aktualisiert dein Paketmanager – der Launcher sagt dir, wenn eine neue Version da ist („Update … verfügbar“), und
verlinkt sie.

## Anmeldeschlüssel und Schlüsselbund

Der Schlüssel, der deine Microsoft-Anmeldungen schützt, liegt im Schlüsselbund des Systems (GNOME Keyring, KWallet,
KeePassXC mit Secret Service …). Ohne Schlüsselbund liegt er in einer Datei, die nur dein Benutzer lesen kann.

**Einstellungen → Speicherverwaltung → Gespeicherte Anmeldungen** zeigt, was genutzt wird. Steht dort **Nur
Dateirechte**:

::steps{level="3"}

### Schlüsselbund einrichten

Installiere und entsperre GNOME Keyring oder KWallet, oder schalte in KeePassXC den Secret Service ein.

### Launcher neu starten

Der Schlüssel zieht von selbst in den Schlüsselbund um.

::

## Probleme lösen

### Leeres oder weißes Fenster

Starte den Launcher mit ausgeschaltetem DMA-BUF-Renderer von WebKit:

```bash
WEBKIT_DISABLE_DMABUF_RENDERER=1 trs-launcher
```

Mit dem proprietären NVIDIA-Treiber macht der Launcher das von selbst. Bei sehr alten Grafikkarten versuch zusätzlich
`WEBKIT_DISABLE_COMPOSITING_MODE=1`.

### Das AppImage startet nicht („FUSE“)

Das AppImage braucht FUSE 2. Installiere es oder starte das AppImage ohne FUSE:

::code-group

```bash [Debian/Ubuntu]
sudo apt install libfuse2
```

```bash [Arch]
sudo pacman -S fuse2
```

```bash [Ohne FUSE]
./TRS-Launcher_<version>_amd64.AppImage --appimage-extract-and-run
```

::

### Minecraft 1.12.2 oder älter stürzt beim Start ab

Alte Versionen (LWJGL 2) brauchen das Werkzeug `xrandr`:

::code-group

```bash [Arch]
sudo pacman -S xorg-xrandr
```

```bash [Debian/Ubuntu]
sudo apt install x11-xserver-utils
```

```bash [Fedora]
sudo dnf install xrandr
```

::

### Das Spiel läuft auf der falschen Grafikkarte

Auf einem Laptop mit zwei Grafikchips schalte **Einstellungen → Standard-Einstellungen → Leistungsstarke Grafikkarte**
ein. Der Launcher setzt dann `DRI_PRIME=1` (AMD/Intel) bzw. die NVIDIA-PRIME-Variablen. Eigene Werte unter
**Umgebungsvariablen** haben Vorrang.

### Werkzeuge wie GameMode oder prime-run

Stell sie unter **Einstellungen → Start-Hooks → Wrapper** vor das Spiel, zum Beispiel `gamemoderun` oder `prime-run`.

### Import aus anderen Launchern

Prism Launcher, MultiMC, die Modrinth App und `~/.minecraft` werden automatisch gefunden, auch ihre Flatpak-Versionen.

::note
Die Flatpak-Version kann nur diese bekannten Ordner lesen. Für alles andere nimm **Ordner durchsuchen** im
Import-Dialog.
::

## Wayland

Der Launcher läuft unter Wayland und X11. Das Spiel selbst läuft über XWayland.

## Unter Linux nicht verfügbar

- **Clip-Aufnahme** und die **Windows-Firewall-Freigabe** (unter Linux nicht nötig).
- **ARM64**: Es gibt keine ARM-Builds, weil Mojang keine Java-Runtime für ARM-Linux hat und Minecraft 1.12.2 und älter
  keine ARM-Natives hat.
